## Decisions that differ from the cloud proposal

The cloud recommends high as the general starting effort for either model. The owner is asking for a particularly demanding reference-matched UI and specifically questioned underusing Astra and Opus. The local addendum therefore proposes xhigh for the first complex screen's contract, writing and review, then a controlled comparison against high. This is an explicit project calibration choice, not proof that higher effort wins or that Opus is the better writer.

The cloud suggests two screen families and four attempts. The addendum begins with one demanding family and two attempts, adding a second comparable family with reversed order if needed. This is a smaller diagnostic exercise, with correspondingly weaker generalization. It cannot establish cost optimality or model superiority.

The cloud uses a separate internal repository-task benchmark. The addendum retains the independently verified SWE-bench Pro comparison, with its harness limitations. Those datasets and cost measures must not be combined. No numeric cloud result was imported as a subscription-quota estimate.

The cloud proposes reviewer high. The initial quality-first candidate uses reviewer xhigh, held identical across writer attempts. Reviewer effort is calibrated separately against frozen candidates, in fresh contexts, with independent adjudication. This prevents changing several variables at once.
