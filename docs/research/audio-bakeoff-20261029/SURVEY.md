# Public-source shortlist, 29 October 2026

Sizes below are representative parameter counts or artifact sizes, **not measured peak RAM**.
CPU/ARM feasibility is an engineering assessment unless a measured receipt says otherwise.
Every deployment must pin the exact weight licence as well as the library licence.

| Candidate | Licence / commercial use | Size | CPU / Linux arm64 | Hindi, Marathi, English, Hinglish / decision |
|---|---|---|---|---|
| [Silero VAD](https://github.com/snakers4/silero-vad) | MIT, yes | downloaded ONNX ~2 MB | ONNX CPU, ARM runtime available; ARM speed unmeasured | Language-independent activity, no words or speaker identity. Test threshold tradeoff; default misses quiet AMI speech. |
| [pyannote 3.1](https://huggingface.co/pyannote/speaker-diarization-3.1) | MIT pipeline; gated download and component licences | segmentation ~1.5M parameters + speaker embedding | CPU possible; PyTorch/torchaudio on ARM require integration proof | Language-independent diarization, Indic accuracy unmeasured. Not source separation. |
| [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) | CC-BY-4.0 weights; gated access, attribution | multi-model pipeline; exact total not downloaded | CPU supported; full ARM dependency/memory proof outstanding | Preferred quality comparator before adoption. Published AMI IHM DER 17.0%, not our result; cannot compare directly with our 120s smoke. |
| [sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html) segmentation + [3D-Speaker](https://github.com/modelscope/3D-Speaker) ERes2Net | Apache-2.0 runtime / MIT downloaded segmentation / Apache-2.0 3D-Speaker code; retain exact weight provenance before production | downloaded int8 segmentation 1.5 MB + embedding 39.6 MB | measured CPU; upstream Linux aarch64 support, target unmeasured | Smallest practical local diarization prototype. Embedding trained on Chinese speech; Indic generalization needs evidence. Two anonymous clusters, no role inference. |
| [NeMo Sortformer v1](https://huggingface.co/nvidia/diar_sortformer_4spk-v1) | **CC-BY-NC-4.0 weights, no commercial adoption**; NeMo code licence does not override weights | ~117M parameters | CPU technically possible; full NeMo stack poor fit for shared 3.8GB; ARM untested | No Indic claim. Reject this exact checkpoint on licence. Later versions need their own review. |
| [NeMo MSDD telephonic](https://catalog.ngc.nvidia.com/orgs/nvidia/nemo/models/diar_msdd_telephonic) | exact NGC model terms must be reviewed; no commercial clearance inferred | decoder download ~103 MB, plus VAD + TitaNet embeddings | CPU possible; multi-model PyTorch stack; ARM untested | Two-speaker phone-call domain is relevant. Not benchmarked; no DER/₹ claim. |
| [Parakeet TDT 0.6B v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) | CC-BY-4.0, yes with attribution | 600M; FP32 weights alone ~2.4GB | ONNX/quantization might fit; full NeMo + weights + activations can exceed 3.8GB; no resize | 25 European languages, **not Hindi/Marathi**. Useful English comparator only. |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | MIT runtime; Whisper MIT weights | tiny 39M, small 244M, large-v3 1550M, turbo 809M | int8 CPU benchmarked here; CTranslate2 ARM CPU support needs exact wheel verification | Multilingual variants support hi/mr/en; code-switch quality must be evaluated. Tiny fails Indic smoke. Model word times are estimates, not certified alignment. |
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | MIT, yes | large-v3 1.55B / turbo 809M; quantized files smaller | native CPU/ARM NEON, strongest deployment alternative; no local timing measured | Same multilingual model family; benchmark quantized turbo on actual t4g before choosing runtime. No claim that x86 speed transfers to ARM. |
| [Distil-large-v3](https://huggingface.co/distil-whisper/distil-large-v3) | MIT, yes | 756M | quantized CPU feasible; ARM via supported runtime | English-only checkpoint; not the Hindi/Marathi replacement. Distillation does not imply multilingual support. |
| [WhisperX](https://github.com/m-bain/whisperX), [paper](https://arxiv.org/abs/2303.00747) | BSD-2-Clause code; ASR, aligner and diarizer licences separately | Whisper + language aligner + diarizer, multiple resident models | CPU mode possible; sequential unload needed on 3.8GB; ARM dependencies unproven | Hindi aligner exists in default map; Marathi must supply/validate a suitable aligner. Mixed-script words may remain unaligned. Better timing requires tested language aligners. |
| [AI4Bharat IndicConformer 600M](https://huggingface.co/ai4bharat/indic-conformer-600m-multilingual) | MIT, gated weights | 600M, FP32 ~2.4GB before runtime | full model/runtime may exceed 3.8GB; ONNX quantized route merits separate test, no resize | Covers all 22 scheduled languages including hi/mr. Not proof of fluent English/Hinglish; explicit language selection and code-switch tests needed. |
| [IndicWhisper / Vistaar](https://github.com/AI4Bharat/vistaar), [paper](https://arxiv.org/abs/2305.15386) | MIT repository; verify selected downloaded model licence | language-specific Whisper checkpoints, inspect exact size before load | quantized conversion possible; large checkpoints exceed practical shared-box FP32 memory | Stronger Indic-specific candidate. Published 39/59 benchmark wins are author's results, not our call-quality evidence. |
| [Sarvam Saaras](https://docs.sarvam.ai/api-reference/speech-to-text/transcribe) | hosted commercial API, no downloadable ASR weight licence established | not disclosed locally | not local CPU/ARM software | Indic/English, verbatim/codemix modes; external audio path remains gated. Not used in this benchmark; do not silently replace local candidate with paid API. |
| [Moonshine](https://github.com/moonshine-ai/moonshine) | current repo says MIT default; listed legacy non-English non-streaming models use non-commercial Community terms | original tiny/base ~27M/62M; newer checkpoints vary | edge CPU/ARM focus | No verified Marathi/Hinglish checkpoint in this review. Check exact language/checkpoint, avoid assuming all weights are MIT. |
| [openSMILE eGeMAPS](https://github.com/audeering/opensmile) | **commercial licence required**, research version prohibited in commercial products | 88 aggregate features, no neural weights for eGeMAPS | native CPU; ARM build feasible but untested here | Useful prosody descriptors, not emotion truth. Not a free commercial replacement. |
| [praat-parselmouth](https://github.com/YannickJadoul/Parselmouth) | GPL-3.0; commercial use allowed subject to distribution obligations | native DSP, no neural model | CPU feasible, ARM source/wheel verification needed | Preferred pitch/intensity comparator; language-independent measurements. Noise/overlap and microphone gain confound interpretation. |
| [SpeechBrain ECAPA](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb) / [emotion](https://huggingface.co/speechbrain/emotion-recognition-wav2vec2-IEMOCAP) | Apache-2.0 cards; dataset/training terms remain separate | ECAPA ~20M; emotion wav2vec2 base ~95M | CPU possible; ARM PyTorch integration untested | Speaker embeddings useful; English acted-emotion training cannot establish Hindi/Marathi caller emotion. No automatic scoring. |
| [wav2vec2 emotion MSP](https://huggingface.co/audeering/wav2vec2-large-robust-12-ft-emotion-msp-dim) / HuBERT emotion variants | selected audEERING card **CC-BY-NC-SA-4.0**; other checkpoints vary | typically 95M–317M backbone | CPU windowed possible; no measured target memory or ARM proof | Reject selected NC checkpoint commercially. Neither backbone name supplies Indic emotion validity or licence clearance. |
| [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) | MIT/Apache-2.0 code; check shipped model notice | DFN3 ~2M parameters, checkpoint-dependent | Rust CPU/ARM feasible, unmeasured | Optional ASR branch only; denoising alters pitch/energy evidence. Keep original clock and original audio for acoustic analysis. |
| [RNNoise](https://github.com/xiph/rnnoise) | BSD-3-Clause code, model notice separately | small recurrent model, checkpoint-dependent | native C, CPU/ARM feasible | Same preservation rule. No speaker separation or transcription. Benchmark noisy speech before enabling. |

Additional benchmark references: [FLEURS paper](https://arxiv.org/abs/2205.12446),
[Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard),
[SDBench](https://arxiv.org/abs/2507.16136). Leaderboard WER is dataset/language-specific;
an English leaderboard rank is not evidence of Marathi or Hinglish performance.
