# AUT-163: restic cache, retention and incremental projection

Source: [AUT-161 read-only evidence](/AUT/issues/AUT-161#comment-6b22fc0a-1f38-49d8-977a-db813fe46694), 30 Sep 2026. The five-minute job never populated the cache; cached September snapshot files appeared at the daily job's 02:xx hour. Cache: root:root 750. Frequent unit: User=root, Group=acops, empty CapabilityBoundingSet. Incident logs expired, so the exact opening failure is unproven. Restic 0.16.4 warns and continues without cache when cache opening fails ([source](https://github.com/restic/restic/blob/v0.16.4/cmd/restic/global.go#L480)). This supports the repository re-read mechanism; it does not establish a leaked-lock incident.

The four entrypoints now test the directory identity and actual writeability, classify cache warnings as failures, and use systemd CacheDirectory provisioning. Daily maintenance runs under the existing flock and a zero-foundation-projection guard: stale-only unlock, logical forget (27h), foundation forget (7/4/6), prune. Foundation dry-run/guard/write follow maintenance. Dry-run `data_added` is new uncompressed blob data; malformed output refuses the write. Sources/excludes are shared. Rebuildable transport/scanner/processing scratch is excluded; native archives, recordings, media objects and operator inputs stay included.
