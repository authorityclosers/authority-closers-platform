This slice adds an authenticated `POST /v1/telemetry/events` batch boundary
(with hidden batch aliases for the existing API namespace). It is
deliberately separate from canonical learning events, outbox facts, audit
records, progress, completion, payment, entitlement, access, and scoring.

## Controlled constraints applied

- Telemetry is the lossy/noncanonical product-analytics plane described by the
  Telemetry and Data/Tenancy sources; persisted rows use the existing
  tenant-scoped `analytics_events` table.
- The server copies the current bounded planning taxonomy into an immutable
  module registry. Unknown event names, versions, payload keys, nested values,
  and PII/secret-shaped values are rejected.
- The authenticated actor supplies tenant, person, and session binding. The
  request cannot choose `tenant_id`, `actor_person_id`, or `subject_person_id`.
- A server-owned consent resolver receives the active caller-owned transaction
  and must return a frozen grant bound to the exact tenant/person/session. The
  route resolves it initially and re-resolves/re-locks the authoritative grant
  immediately before insert; status, purpose, or identity changes deny the
  write. An explicit retention policy and a
  tenant-aware admission seam are also required; the shipped application
  composition supplies none, so writes fail closed. Client-supplied consent is
  not part of the intake schema.
- Event IDs are controlled UUID tenant-scoped replay keys. Exact replays are classified as
  duplicates; a changed observation for an existing ID returns a conflict and
  never overwrites the original row.
- Route metadata is limited to exact server-owned learner route templates and
  trace IDs are generated by the server; request correlation headers are never
  persisted as telemetry metadata.
- Batch count, serialized request, per-event payload, timestamp age, and future
  skew are bounded. Admission is required and injectable for a distributed/edge
  tenant-aware queue/quota. The application adds only a coarse route-specific
  rate/body limit; a deployment must compose durable distributed admission
  before enabling writes.
- Stored provenance/retention fields are `trace_id`, `release_id`, session ID,
  consent policy/capture time, retention policy ID, and retention expiry. The
  response exposes a stable source/version label without echoing input data.
- Expired rows are hidden by a non-mutating `retention_expires_at > now` read
  predicate. Physical expiry is enforced by `TelemetryRetentionJob`/
  `run_telemetry_retention_job` in an explicit caller-owned transaction and is
  policy-scoped; learner reads do not authorize expiry.
  `TelemetryAccountDeletionHook` provides an explicit processing/completed
  deletion-request gate for purge or bounded anonymization. Available batches
  drain before completion; a zero-progress pass with locked work returns a
  continuation signal and leaves the deletion request processing for a later
  durable retry. Legal-retention policy classes and non-enum deletion actions
  fail closed here.
- The taxonomy remains proposal-only and promotion pending. It must not be
  treated as a canonical metric definition or activated with an external
  analytics provider without the controlled promotion and governance gates.

## Changed implementation

- `packages/python/ac_platform/telemetry/ingest.py` — server-owned event/batch
  contracts, privacy checks, timestamp/size bounds, consent and admission
  ports.
- `packages/python/ac_platform/http/telemetry.py` — authenticated route,
  fail-closed composition, derived scope, replay handling, and safe generic
  validation errors.
- `packages/python/ac_platform/learning/planning_repository.py` — append-only
  batch insert/replay classifier plus explicit policy-scoped expiry seam for
  the existing disposable analytics table.
- `packages/python/ac_platform/telemetry/retention.py` — durable retention job
  and account-deletion/anonymization hook; legal-retention distinction is
  fail-closed.
- `packages/python/ac_platform/identity/application.py` and
  `packages/python/ac_platform/http/auth.py` — optional same-transaction
  identity deletion privacy-hook seam with bounded-batch drain/continuation;
  the shipped app leaves it uncomposed until a controlled retention policy is
  approved.
- `packages/python/ac_platform/http/app.py` — route composition with no consent
  or retention/admission activation; legacy `/v1/analytics/events` is omitted.
- `packages/python/ac_platform/http/rate_limits.py` and
  `packages/python/ac_platform/http/request_limits.py` — route-specific abuse
  and body-size seams.
- `tests/unit/http/test_telemetry_routes.py` — contract coverage for consent,
  scope, privacy, timestamp, bounds, UUID replay, identity mismatch, route and
  trace metadata, admission, taxonomy, and persistence.
- `tests/unit/telemetry/test_retention.py` — durable expiry, transaction and
  policy gates, account-deletion scope, anonymization idempotency, >batch and
  locked-work continuation, enum validation, and legal-retention fail-closed
  coverage.
- `tests/unit/identity/test_hardening.py` — account-deletion drain and locked
  continuation orchestration coverage.
