# Canonical authorization CLI — implementation checkpoint

Date: 2026-09-08. Source and synthetic tests only; **no provisioning command or runtime activation**.

The new [`python -m ac_platform.authorization`](../../packages/python/ac_platform/authorization/cli.py) adapter exposes `inspect`, `first-manager`, `grant`, and `revoke`. Every command requires an explicit environment and subject Person UUID; optional expected email is only an exact consistency check. Mutations require an explicit UUID intent and non-secret reason. Grant additionally requires an individually supported capability and valid platform/tenant/program scope; revoke must address a grant belonging to the supplied subject.

Configuration, arguments, scope, production acknowledgement, explicit database, operations tenant and immutable deployed release are checked before connecting. Only `first-manager` uses the existing operator bootstrap: an already verified active operations owner, once before capability history, with no identity, membership or session creation. The other commands require a real opaque session read from bounded hidden input (43–512 characters), never arguments. Windows input has no echo; POSIX echo is restored even on failure; non-terminal input has a fixed read bound. No echoed-input fallback exists.

The package-internal canonical governance fence precedes normal identity resolution. Existing `CapabilityApplication` remains the authority for manager checks, resource scope, grant/revoke and immutable replay. Subject identity is locked through email comparison and the command. Audit and assignment commit together before a safe ID/status summary is printed. Native exceptions and offending parser values are not printed. Unknown failures retain the original command intent for safe retry. A revoked grant replay reports `active: false`, not renewed authority.

Inspection requires an existing manager, is bounded to 200 history rows, and rolls back its transaction, including normal session last-seen updates. It explicitly reports that effective access was not evaluated; historical revocation state is not a permission decision. No platform capability is mapped to a tenant role or generic catalog authority.

Validation: **158 passed in 17.44 s** across authorization and bootstrap unit suites, including **52 new CLI tests**. Real foreign-key-enforced SQLite tests execute canonical identity, session, grant/revoke and audit logic; prove rollback after real audit/commit failure, read-only inspection, role preservation, subject/lifecycle denials and governance-before-identity ordering. Terminal adapters and boundary failures use synthetic inputs. Scoped Ruff formatting/lint, CLI mypy and diff checks passed. PostgreSQL CLI execution and independent parent review remain separate gates; SQLite does not prove PostgreSQL locking. Platform admission/enforcement is a separate integration slice.
