This change reuses C1 checkout and verified settlement, including their copied
plan, subscription quantity, monthly/yearly lots, replay handling and renewal.
It adds:

- An Enterprise minimum of 50 seats at checkout (`422 seats_out_of_range`).
- Seat enforcement under the existing organisation registry write lock.
  Active members (including the owner) plus pending invites consume seats.
  An unpaid organisation has zero paid seats; additions fail with
  `409 seats_full`. Accepting a pending invite replaces its reservation.
  Successful retries return their original audited result before enforcing
  capacity again. Existing active members and role changes consume no new seat.
- Seat capacity from the immutable subscription's current paid period and its
  unclosed ledger grant. Provider/order status grants neither seats nor minutes.
  Rollover preserves minutes but does not extend the paid period's seat capacity.
  Refund closings and holds are netted against the supporting grant.
- A pool read that uses the existing billing projection over organisation lots
  and tenant-scoped reservation/settlement usage, including former members.
  It creates no account or trial grant. Pool admission remains on AUT-954.
- An owner-only seat-count read. Members can read the shared pool and their own
  member detail; owners/admins can read the member directory's existing scope.

Small necessary scope additions: fixture updates only in
`tests/integration/test_organisation_activity_postgresql.py` and
`tests/unit/http/test_platform_organisations.py`. Both exercise the same audited
member service and must seed paid capacity under the new rule. No additional
production files were changed. Existing membership fixtures now have fictional

## Final JSON contracts

The following examples use fictional identifiers and values. All GETs require
canonical cookie authentication and an active selected organisation, and return
`Cache-Control: private, no-store` and `Vary: Cookie`.

`GET /v1/organisation/usage` returns integer seconds and the existing strict
member row shape. `used_seconds` includes pending reservations at their reserved
amount and settlements at their charged amount. `balance_seconds` can be
negative; `available_seconds` is floored at zero. A member's example:

```json
{
  "available_seconds": 119940,
  "balance_seconds": 119940,
  "used_seconds": 60,
  "members": [
    {
      "person_id": "11111111-1111-4111-8111-111111111111",
      "invite_id": null,
      "name": "Fictional Rep",
      "email": "rep@example.test",
      "role": "member",
      "status": "active",
      "joined_at": "2026-10-03T23:00:00+00:00",
      "last_active_at": "2026-10-03T23:00:00+00:00",
      "minutes_used_30d": 1.0,
      "calls_30d": 1
    }
  ]
}
```

`GET /v1/organisation/billing` is owner-only (`403` for admins/members):

```json
{
  "paid_seats": 2,
  "active_members": 2,
  "pending_invites": 0,
  "seats_available": 0
}
```

`POST /v1/organisation/members` keeps its current email/role request,
canonical UUIDv4 `Idempotency-Key`, and `MemberResponse` success shape. A full
organisation returns the existing problem-details envelope with:

```json
{
  "type": "https://authorityclosers.com/problems/seats-full",
  "title": "Organisation seats are full",
  "status": 409,
  "detail": "All paid seats are occupied by members or pending invites.",
  "instance": "/v1/organisation/members",
  "code": "seats_full",
  "request_id": "unavailable"
}
```

The selected-organisation purchase request remains C1:

```json

  "account": "organisation",
  "plan_key": "organisation",
  "interval": "month",
  "seats": 2
```

Prices and allowed Organisation seat ranges remain catalogue-controlled. The
