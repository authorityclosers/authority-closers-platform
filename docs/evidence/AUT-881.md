## Missing Personal-account purchase contract

At the source revision above:

- `billing/checkout.py:resolve_account` requires the organisation registry row
  and the buyer's active owner membership before organisation checkout.
- `billing/checkout.py:_subscription_checkout` stores the organisation account
  on both the order and subscription before it returns hosted checkout.
- `http/billing.py:CheckoutRequest` and `billing/commands.py:CheckoutCommand`
  have no new-organisation name or deferred organisation intent.
- `http/organisation.py` has no `POST /v1/organisations` create route.
- `organisations/service.py:create` supplies audited operator creation. It is
  not the O1b public create contract with verified-account and ownership-limit
  checks.
- Migrations 0062, 0063 and 0064 prohibit updates/deletes of billing accounts,
  orders and subscriptions. Fulfilment cannot move an existing Personal billing
  reference to a newly created organisation by updating history.

The task says a verified payment creates the organisation for a Personal buyer,
but also requires reuse of O1b creation. The current implementation requires the
organisation before checkout. Resolving the creation timing affects the shared
checkout contract and identity boundary; it is a CTO decision under escalation
rule 2, not a lane-gate conflict.

Decision needed: does the Personal buyer create/select the organisation through
O1b before checkout, or must organisation creation wait until a verified charge?
The former reuses the existing account/order structure; the latter needs an
approved append-only intent/fulfilment design and an expanded implementation
boundary. No such design is inferred in this run.
