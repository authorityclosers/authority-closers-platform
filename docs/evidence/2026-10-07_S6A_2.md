## Implementation

- `python -m ac_platform.payments.cli enqueue-expiry --environment <environment>`
  requires matching explicit `AC_ENVIRONMENT`, environment-injected
  `AC_DATABASE_URL`, enabled billing and distinct configured public/operations
  tenants. Staging/production additionally require the immutable API image's
  baked release identity. No settings are changed by this command.
- Compatibility choice: one existing `billing.capacity_expiry.v1` job per
  account per UTC date, deduplicated by `<job_kind>:<account_id>:<YYYY-MM-DD>`.
  The injected clock is timezone-aware and normalized to UTC once per pass.
- Select public Personal accounts and non-public Organisation pools, excluding
  operations and isolated member accounts. Each account transaction takes the
  shared recovery lock, then the existing tenant admission lock, then enqueues
  exactly `{"account_id": "<uuid>"}` with `external_side_effect=False`.
  A partial pass can restart without losing committed intents or duplicating
  them. The repository's existing retry/lease limits remain in force.
- Enqueue writes no accounts, lots, closings, provider or order state. The worker
  remains responsible for source-reference replay, pending-allocation deferral,
  atomic closing/audit/success, lease fencing and internal retry. The next UTC
  day supplies another intent for pending lots. Annual future lots activate
  through projection without a scheduler.
- The reviewed timer is daily at `00:15 UTC`, persistent after downtime, with
  one-minute accuracy. The oneshot unit runs as UID/GID 10001 with filesystem,
  privilege and resource restrictions. It enqueues only; it starts no worker.

Successful CLI output counts scheduled accounts including equivalent replays:

```json
{"job_kind": "billing.capacity_expiry.v1", "run_date": "2024-03-31", "scheduled_accounts": 1}
```

Failures return exit code 2 and only `billing_maintenance_refused` on stderr;
raw database/configuration/exception text is never emitted by the CLI.

## Isolated dev/staging check

The focused test runs the real async CLI database path twice against separately
migrated loopback PostgreSQL schemas with fictional data, under development and
staging composition fixtures. It injects the existing trial/tenant configuration
and a fictional baked-identity verifier; this is not an installed environment
or immutable-image verification.

Each profile starts with an expired 600-second lot, an unexpired 300-second lot
and an expired derived trial. The first enqueue/worker pass writes exactly one
600-second expiry and audit. The second enqueue returns the same account count,
preserves the succeeded job and original lot history, and leaves the worker
idle. Available and statement balances both read 300 seconds. A Kolkata clock
at 1 April midnight produces the correct 31 March UTC dedupe date.

Other fictional PostgreSQL checks cover simultaneous enqueue, pool/member scope,
partial-pass rollback/restart, held recovery, pending/no-work next-day expiry and
future lots remaining available without an activation job. Existing expiry,
period, projection, job lock/replay and golden-v1 tests cover the unchanged
accounting boundary.
