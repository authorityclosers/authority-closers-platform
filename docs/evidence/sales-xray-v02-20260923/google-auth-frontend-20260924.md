# Sales Xray Google completion and age acknowledgement, 2026-09-24

The existing combined Google sign-in and account creation action now uses the full age, Terms, and Privacy acknowledgement. The email code request sends `age_attested: true` only after acknowledgement; the Google start query sends `age_attested=true`, consent, and the current consent version after a fresh configuration read. If email codes are disabled but Google remains enabled in a valid configuration, Google and its acknowledgement remain available.

The Google callback accepts only one UUID flow and one allowlisted `auth_result`. It forwards only that flow and result to the original window. The original window checks the message origin, source, flow, and shape; on `success`, it requires a matching `/v1/auth/google/completion` receipt before reading the canonical session. A manual recovery click inspects only the exact same-origin callback URL and follows the same receipt path. `failed`, `review_terms`, and `unavailable` end the popup attempt without reading an existing session; `review_terms` clears the acknowledgement and reloads configuration. This is frontend behavior only; the backend receipt and callback are owned by the separate server implementation.

Verification: focused Vitest suite passed (3 files, 25 tests) and Sales Xray TypeScript check passed. Tests use mocked network responses, synthetic UUIDs, and a synthetic local filename. They cover mismatched popup origin/source/flow, unmatched receipt with an existing session, review of changed terms, manual callback recovery, and independent Google availability. No real account or Google traffic was used.
