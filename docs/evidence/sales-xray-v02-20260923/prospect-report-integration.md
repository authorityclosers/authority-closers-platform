# Prospect report integration

The first v0.2 report workflow now exposes Overview, Prospect, Moments, Sales skills and Next-call plan. The reusable Prospect component consumes only validated, visible `overview.prospect_interpretations`. It separates the report observation and unchanged source quotation from the possible-concern hypothesis, links to the existing audio dock, and labels its scope as this call only. It does not synthesize a persistent person profile or infer hidden guest findings. Preview counts and the existing account-unlock action remain server-controlled.

`9740cc81` contains the component and five passing focused tests. Integration adds compact mobile tab labels while preserving full accessible names, 44-pixel minimum mobile tab targets, and scroll clearance for keyboard focus below sticky tabs. The combined studio, explorer and Prospect suite passed **75 tests**. The extended audio test verifies that selecting Prospect evidence seeks the same audio element and that changing report tabs neither remounts the source nor uploads/accepts another analysis. App TypeScript and full ESLint checks passed.

Chrome at 390×844 and 320×740 showed five tabs without horizontal overflow. At 320 pixels all tabs measured at least 44×44 pixels; Tab navigation reached the source playback action above the fixed audio/navigation docks. A keyboard-focus overlap beneath the sticky tabs was found and corrected with scroll margin. The private visual fixture serves only synthetic data and refuses all non-GET requests; its unavailable audio is not a playback pass. The separate compiled API/database browser gate verifies actual playback.

The component follows the harvested desktop/mobile report references' mint evidence and violet hypothesis grouping, with responsive stacked cards and reduced-motion support. The existing broader shell is retained for this first release; this record does not claim the complete future v0.2 visual design or live-provider report quality.

Additional browser checks used a long Hindi/Marathi/English hypothesis (578 characters including the section labels) at 320×740 and 1440×900. The text wrapped without horizontal clipping and the original mixed-script quote remained unchanged. The report-language metadata is visible on mobile; only the decorative header tagline is hidden. A deliberately overlong fixture was rejected by the existing 700-character field contract, with saved work retained; correcting the fixture and using GET-only Check again recovered the report. All temporary viewport settings were reset.
