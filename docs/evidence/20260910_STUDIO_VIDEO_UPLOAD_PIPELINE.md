# Course-scoped video upload foundations — 2026-09-10

Status: local implementation and test evidence only. Not a completed upload UI, media processing deployment, production activation, or proof of long-video playback.

## Implemented

- Course-scoped video upload admission and status routes, available only through fresh authorized Studio access. Request scope is server-resolved; callers cannot supply a tenant, replacement asset, publication state, or completion state.
- Append-only course/upload association with tenant-aware foreign keys, a forward migration (0026), ORM protection, and PostgreSQL update/delete rejection triggers.
- Existing quota, checksum, upload-intent and idempotency machinery reused through a narrowly bound, one-use Studio authorization. Actor permissions are not broadened. Concurrent requests lock course then actor consistently; duplicate admission does not duplicate intent, quota reservation, or audit.
- Status is owner/course/tenant scoped and returns no storage key, private URL, checksum, or internal processor error. Unconfigured video storage remains unavailable rather than accepting an upload that cannot work.
- Explicitly configured streaming ClamAV adapter. Disabled without configuration; accepts only local Unix socket or literal loopback endpoints, bounds chunks/response/time/size, validates source identity/checksum, and rejects malformed, incomplete, malware and error responses. No ClamAV daemon was installed or activated by this change. Deployment must separately verify daemon configuration, signatures and scan limits.
- Worker job-kind isolation at both claim selection and conditional take. The email worker cannot take queued video-processing work merely because it shares the jobs table.
- Explicit private video filesystem byte adapter (not runtime-composed): bounded streaming writes, declared length/checksum verification, immutable destination versions and private range reads. Interrupted writes are never exposed as complete objects; crash leftovers stay charged for later explicit reconciliation. Metadata does not grant access or imply scanning/publication.
- Optional provider-neutral `StreamingPrivateObjectWriter` capability. FFmpeg's generated outputs now use bounded one-MiB chunks instead of `Path.read_bytes()` for a whole lecture. Legacy non-streaming adapters accept small outputs only; large unsupported transfers fail before allocation/write. Output quota decreases after each actual file transfer.
