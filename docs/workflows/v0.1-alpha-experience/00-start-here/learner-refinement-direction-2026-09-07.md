# Learner journey refinement — direct user feedback, 7 September 2026

This supplements the existing Alpha acceptance contract. It does not mark Alpha
accepted, replace controlled business rules, restart the product, or postpone the
already-verified incremental release. The user explicitly requires consistent
quality throughout the learner journey, not only the dashboard and course cards.

## Settings, profile and progress references

The user supplied four screenshots comparing compact categorized settings and a
clear personal profile with the current AC settings screen. Use the interaction
hierarchy as inspiration, not ChatGPT-specific features, account metrics or branding.
The attached images contain personal account details: do not publish them as AC
test evidence or upload them as release screenshots.

- Settings: a bounded, searchable category navigation and one active content panel
  on desktop; full-screen category/detail navigation on mobile. Compact labeled
  controls, visible save/validation state where applicable, keyboard navigation,
  browser history/deep links and unsaved-change protection. Do not display a large
  document of every settings card at once. Existing appearance storage semantics,
  preferences, account verification and permission boundaries remain truthful.
- Profile: clear identity and meaningful real accomplishments, with a next action.
  No invented streaks, badges, public visibility, mastery scores or completion.
- Progress: first answer what is complete, what remains and what to do next.
  Any chart must explain a useful question, use canonical source-backed measures,
  and distinguish unavailable data from zero. Activity volume is not mastery.
- Auth, recovery and onboarding: the same typographic/control quality, concise
  guidance and explicit recoverable states. All remain in the route inventory.

## Notification example and cross-journey quality rule

The user supplied the current disconnected notification popover. It repeats its
unavailable state, exposes implementation jargon, consumes excessive space and
offers a destination that repeats the same unavailable state.

Required correction: one compact honest unavailable state, useful navigation to
an existing destination, proper bell/close/focus behavior, and no fabricated unread
count or 'all caught up' state. A genuinely empty connected feed is a different
state. Frontend polish does not count as implementing the missing server feed.

Across the journey, remove user-facing engineering phrases such as 'first slice',
'server-backed', 'account control surface', and unnecessary API explanations.
Explain the user's available action and outcome. Keep deeper technical information
in appropriate diagnostics/evidence, not repeated warning cards.

## Verification before calling this complete

Capture actual before/after settings, profile, progress, notifications, auth and
onboarding states at desktop and small mobile widths. Exercise category switching,
search, history, keyboard focus/Escape, save validation, reduced motion, theme,
loading/empty/unavailable/failure and recovery. Confirm no dead-end CTA and no
fabricated canonical status. Existing four-route layout passes are partial evidence,
not a percentage of whole-product completion or final design acceptance.
