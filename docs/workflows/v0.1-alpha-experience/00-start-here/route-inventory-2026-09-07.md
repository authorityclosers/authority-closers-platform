# v0.1 Alpha — exact route and mounted-runtime inventory

Date: 2026-09-07. Scope: current `d2de` implementation worktree, not a deployed-build or acceptance claim. This is a source census supporting the [Alpha acceptance contract](alpha-acceptance-contract-2026-09-07.md); it does not freeze the action/state acceptance denominator.

## Counting rule and evidence boundary

Discovery command, from the repository root:

```powershell
rg --files apps/learner-web/app apps/admin-web/app -g page.tsx
```

| Application   | Product-rendering page templates | Compatibility redirects | Development-only entry points | Total exact `page.tsx` files |
| ------------- | -------------------------------: | ----------------------: | ----------------------------: | ---------------------------: |
| `learner-web` |                               26 |                       0 |                             1 |                           27 |
| `admin-web`   |                                8 |                       1 |                             1 |                           10 |
| Total         |                               34 |                       1 |                             2 |                           37 |

These are route templates, not the number of instantiated program/activity URLs, authorized actions, or completed journeys. The two applications have separate origins: their `/` and `/login` paths are not duplicates. A product-rendering page may honestly expose a locked or unavailable capability; its presence does not establish end-to-end availability.

Excluded: `components/auth-flow-page.tsx` and `components/policy-page.tsx` (components, not routes); `route.ts` API/proxy handlers; metadata/manifest/icon files; layout/loading/error/not-found boundaries. `ROUTES.practice` is `/home#practice`, not a `/practice` page. Route aliases such as dashboard/learnerHome and learning/myLearning do not add pages. Query-selected preview/recovery states also do not add routes.

Current consolidation browser evidence covers **Discover and Learning only, and is partial**. No other route is claimed browser-accepted by this inventory. Source inspection, an existing test filename, a development harness, or a passing aggregate test command is not a substitute for exact-candidate route/action/state browser evidence. Full validation is owned by the main delivery lane and was in progress while this inventory was written.

## Acceptance work still to freeze

This census does not set a completion ratio. For every in-scope journey, the main lane still needs a frozen action/state list with owner, applicable access context, real data/provider prerequisites, desktop/mobile and keyboard evidence, and the exact candidate revision. Keep gated capabilities visible as gated; do not remove them from scope silently or mark a locked command as an executed journey.

Existing targeted automated evidence entry points include learner `direction-a-shell.test.ts`, `dashboard-runtime.test.tsx`, `learning-loop-runtime.test.tsx`, `learner-runtime-concurrency.test.ts`, `profile-runtime.test.tsx`, `settings-runtime.test.tsx`, `notifications-runtime.test.tsx`, `theme-runtime.test.tsx`, and `pwa-assets.test.ts`; admin `admin-access.test.ts`; and `tests/e2e/test_local_bridge_cookie_isolation.py`. These filenames identify existing checks, not current pass claims or comprehensive route coverage. Aggregate validation and exact-build browser/media evidence remain separate records.
