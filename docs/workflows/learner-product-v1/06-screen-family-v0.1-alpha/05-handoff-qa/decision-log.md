# Decision log

## DLG-LSF-001 — Isolated package boundary

Date: 2026-09-03 · Status: accepted for this handoff

Create a new folder under `docs/workflows/learner-product-v1` so the package
does not overwrite the neighboring visual exploration or in-progress app
changes. Existing sources and neighboring packages remain authoritative where
this folder does not explicitly add a contract.

## DLG-LSF-002 — Behavior before pixels

Date: 2026-09-03 · Status: accepted

The package is contract-ready with visual generation pending. No raster,
Figma, Canva, Lucid, Drive-upload, or Notion artifact is claimed. If visual
exploration starts later, it must produce exactly three independent directions
before selection; behavior remains governed by the state matrix.

## DLG-LSF-003 — Plan horizons are bounded projections

Date: 2026-09-03 · Status: provisional design inference

Today/Week/Month are subviews under `/home`, not new authoritative schedule
routes. They display only canonical plan/calendar data or explicit learner
intent. Empty/unavailable states must not invent deadlines, cadence,
appointments, reminders, coach commitments, or completion values. The IA/API
owner must confirm any future route or persistence contract.

## DLG-LSF-004 — Activity and progress semantics

Date: 2026-09-03 · Status: controlled constraint

Watch → Reflect → Implement → Review → Improve reuses the permanent Activity
kernel. Video coverage is unique server-authoritative intervals under a
versioned policy; the 90% default is provisional participation evidence, not
mastery. Progress/completion/evidence are canonical server state and analytics
is observational only.

## DLG-LSF-005 — Profile/avatar scope

Date: 2026-09-03 · Status: contract-first / gate-blocked

Avatar crop and replacement states are specified because the screen family
needs a safe user experience, but provider/upload/object processing activation
is not claimed. The prior avatar remains current until a server-confirmed new
revision; prior history is superseded under the approved retention policy.

## DLG-LSF-006 — Theme variants

Date: 2026-09-03 · Status: accepted candidate

Light is the default theme mode; Dark and System are device-local mode choices,
and System follows the browser/device preference. Named presets plus accent,
density, and motion are additional browser-local presentation variants.
Storage failure falls back to a usable current/System presentation. Theme and
appearance cannot change identity, account, tenant, authority, consent, access,
notification, progress, certificate, or session state.

## DLG-LSF-008 — Settings screen-ID and appearance-contract reconciliation

Date: 2026-09-04 · Status: accepted reconciliation

The current settings registry and learner-product screen family are authoritative:
`SET-01` is verified account, `SET-02` is appearance, `SET-03` is learning
setup, `SET-04` is security/privacy, and `SET-05` is session. Older
`v0.1-alpha-experience` references that grouped the last two capabilities under
different IDs are normalized to this mapping; no new capability or protected
business meaning is introduced. The appearance contract keeps Light/Dark/System
as theme mode and treats named presets, accent, density, and motion as
browser-local presentation-only values, never account, tenant, or authority
state.

## DLG-LSF-007 — Unresolved evidence gates

Date: 2026-09-03 · Status: open, capability-specific

Exact-current runtime, caption/transcript/media evidence, avatar provider
contract, certificate issuance, plan semantics, PWA/browser/device behavior,
accessibility testing, and release proof remain open. These gaps do not block
the documentation package; they block only the affected capability or its
production approval.
