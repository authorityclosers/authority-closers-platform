# Learner workflows

## WF-01 Resume learning

Dashboard -> Continue learning -> Activity -> deterministic completion evidence
-> next activity -> Dashboard/My Learning updated from canonical projection.

## WF-02 Browse and start a program

Discover -> filters/search -> Program detail -> eligibility/entitlement check ->
explicit start/enroll action -> My Learning -> Course overview. Paid commerce
remains gated; a teaser cannot grant access.

## WF-03 Complete Module 1

Watch -> Choose -> Sequence -> Apply -> Review. Each activity exposes its own
default, loading, locked, offline, save/submit, retry, and completed states.
Evidence is deterministic. Optional notes may exist but are never the primary
interaction.

## WF-04 Manage learner identity

Avatar -> Profile -> select/upload photo -> server validation and processing ->
private object reference revision -> shell/profile refresh. Replaced photos are
superseded under retention/audit rules rather than silently overwritten.

## WF-05 Change preferences

Avatar/More -> Settings -> section -> edit -> validation -> revision-aware save
-> durable confirmation. Light is the default product presentation; theme
selection does not alter permissions or content.

## WF-06 Review progress

Progress -> choose course/range -> view canonical completion and separate
descriptive analytics -> open module/activity. Unknown/unavailable is distinct
from zero. Analytics events never become access or completion authority.

## WF-07 Notifications

Header bell or More -> Notifications -> read/open -> deep link to owned surface
-> notification read state. Delivery preferences remain separate from learning
state and commercial consent.

## WF-08 Media playback

Activity -> playback policy resolver -> media delivery port -> VPS-origin
adapter -> signed manifest/source -> player -> captions/transcript/resume ->
playback evidence -> canonical progress projection. A future CDN adapter may
replace the VPS adapter without changing the activity route or domain contract.
