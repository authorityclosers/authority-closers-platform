# Review 2.0: reviewers judge the analysis, not the report (19 Oct 2026)

On 19 Oct the owner asked for four things:
- Review must not depend on the Report's design, which keeps changing.
- Reviewers judge the underlying analysis (the objects and the objective data) in sales and psychology terms.
- Coaching review is separate.
- Review pipelines are configurable, built on base primitives. Reuse the gold rows.

## What exists today

- **Gold review (0094, gold-review-phone chat).** A reviewer roster (`conversation_gold_reviewers`), assignments per call and reviewer, and append-only gold rows. Each row holds a target, a digest of the AI content judged, a payload, a supersede chain and erasure.
  - Every assignment requires an AI pointer review (`review_id NOT NULL`), so gold review is tied to the Report: one row per report line, 29 per call.
- **Call data engine (0097).** Typed call objects, facts with evidence, segments and voice. `call_object_decisions` holds a person's word on an object (asked, auto_filled, accepted, edited, rejected), and it can write Lead Desk fields.
  - That is product data. A reviewer's quality judgment must never change it.

## The design

**Targets are analysis, never report lines:**

| Target | What it is |
|---|---|
| object | One call object: a need, objection, commitment, person, money, signal, decision or friction |
| fact | One current fact with its evidence |
| segment | A labelled stretch of the call: intent, act, sentiment, tone |
| voice | Talk share, pace, pauses, overlap |
| coaching | One coaching point. Coaching runs as its own pipeline, judged in coaching terms |

Each verdict carries a digest of the AI value it judged. When the engine changes that value, the verdict stays attached to the old value and does not pass silently onto the new one.

**Base primitives.** A pipeline is an ordered list of these, stored as versioned JSON:

| Primitive | What it does |
|---|---|
| sample | Picks calls and targets by organisation, type, confidence band, pipeline or version, at random or newest first, with a limit |
| show | Shows the target with its evidence (the quotes jump the player), a transcript window and voice, never the report layout |
| ask | One question. Kinds: verdict (correct, wrong, unsure), pick (from a taxonomy, such as the right objection type or the buyer's emotional state), correct (free text or a value), scale (1–5) |
| reconcile | When two reviewers disagree, a third one decides |
| measure | Agreement by target type, model, prompt version and pipeline version, which feeds Admin's Analysis health and the model bench (Phase 5) |

**Pipelines to start with (configurable in Admin):**
1. **Analysis: sales.** Objects and facts. Asks whether each is correct, its right type, and its right value.
2. **Analysis: psychology.** Segments and voice. Asks for intent, buyer emotion (a pick list), tone, and whether this moment was handled well.
3. **Coaching.** Coaching points only. Asks whether the point is true, whether it is useful, and whether it shows the right moment.

**Storage, new migration (0100, number to be confirmed with Align 3):**
- `review_pipelines`: key, version, kind (analysis or coaching), title, definition JSON, created by, created at. Append-only; the newest version is the active one.
- `review_verdicts`: pipeline key and version, recording, tenant, reviewer, target kind and reference, AI digest, question key, answer JSON, supersedes, request key (idempotent), created at, erased at.
  - Append-only, the same rules as gold rows. Call erasure reaches verdicts.

**What is reused:**
- The gold reviewer roster (`conversation_gold_reviewers`): the same people review, with no second designation.
- The gold row rules: supersede rather than edit, an AI digest, idempotent requests, erasure.
- Existing gold rows count as the pipeline "report lines v0" in Measure, so nothing collected is lost.
- The phone `/review` shell and alerts (gold-review-phone): Review 2.0 tasks appear there as well.

**Never:** a verdict writes neither to call objects, nor to decisions, nor to Lead Desk fields.

## Slices

1. Migration 0100, the models and the read/write API (operations reviewers, audited), plus one default pipeline, "Analysis: sales".
2. Admin: verdict chips on the call page's Analysis tab (correct, wrong, unsure, with a correction), and a review queue sampled by the pipeline.
3. The pipeline editor in Admin → All settings, built from the primitives.
4. Psychology and Coaching pipelines; reconcile.
5. Measure in Analysis health: agreement by type, model and version.
6. Phone: Review 2.0 tasks in `/review`.
